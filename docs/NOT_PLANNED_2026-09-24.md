# 明确不做的功能

> 2026-09-24 · 对应版本 2.5.0
> 需求来源：用户提出「值得做但还没做的功能，明确都不做，写一个文档」。
>
> 这份文档记录的是**决定**，不是待办。每一条都写清楚了「技术上怎么做」——
> 也就是说这些点都是可扩展的，不做的原因是产品取向，不是做不到。

## 一、三条判断标准

任何一个"要不要做"的问题，先过这三条：

1. **看清 vs 代打。** 只做「帮你把局面看清」的，不做「替你把游戏玩掉」的。
   看数据、发自己写的消息、把信息摆到面前——做；替玩家判断、替玩家出手——不做。
2. **不可逆 / 对外可见。** 会替玩家做出**别人能看见**的决定（点赞、进别人的房间、秒退、开局）的，一律不做。
   错误判断的代价必须由**按下按钮的人**当场承担，而不是事后才发现。
3. **只碰本地只读接口。** 能力来源限 LCU / Riot Client / SGP 的只读或幂等接口。
   需要注入、读内存、模拟输入的**局内自动操作**是红线，不讨论。

> 唯一的表面例外是快捷消息发送（`Ctrl+F5` 等确实模拟键盘）。它不违反第 1、2 条：
> **文本是玩家自己写的，键是玩家自己按的**，工具没有替任何人做判断。

## 二、逐条：不做，以及为什么

### 1. 自动荣誉（auto honor）

- **AK 对应**：`AutoGameflowHonorController` —— 读荣誉投票的候选（己方/对手、剩余票数），
  随机投给己方，优先当前房间内的成员，顺带取消"再来一局"。
- **不做的理由**：荣誉是**给别人的社交评价**。随机投等于把玩家的社交表达变成噪声，
  被点赞的人也拿不到任何真实反馈；而它对玩家自己的收益（荣誉等级）与"看清局面"无关。
  一句话：**收益归自己、代价由别人承担**的功能不做。
- **若要捡起来**：荣誉投票接口拿到候选与票数 → 新的 `lol.auto_honor` 命令。
  真要做，缺的不是接口，而是"为什么随机点赞比不点更好"这个答案。

### 2. 自动接受邀请（好友 / 房间邀请）

- **要区分清楚**：我们**已经有**「自动接受对局」（`automation.autoAccept`）——
  那是自己排到队之后的准备确认，**不涉及任何第三方**。这里说的是接受**别人发来的邀请**。
- **AK 对应**：`invitation-controller`，按邀请类型走不同策略自动进房。
- **不做的理由**：接受邀请会**替玩家进入别人的房间**，对外可见且不可逆——
  队友会看到你进来了。而拒绝的成本远低于误接受。社交关系应当由人确认，
  我们对"删除好友"都做成了软删除 + 恢复需对方同意，同一个原则。
- **若要捡起来**：`/lol-lobby/v2/lobby/invitations` 列表 + `.../:id/accept`。

### 3. 自动秒退 / 自动躲选人（remake / dodge）

- **AK 对应**：`/lol-gameflow/v1/session/dodge`。
- **现状**：我们**已经有手动的「英雄选择秒退」**（在客户端急救里，且有二次确认）。
  差额只在于"要不要自动触发"。
- **不做的理由**：秒退有**惩罚队列**，代价直接落在玩家账号上。
  自动触发意味着**一次误判要玩家付出 30 分钟**。凡是"替玩家花掉真实代价"的操作，
  必须由人手动按。我们的急救面板正是这么设计的：有副作用的两个动作（秒退、退房间）保留二次确认。
- **若要捡起来**：不建议。真要加，至少默认关闭 + 每次确认。

### 4. 复活计时器（respawn timer）

- **AK 对应**：`respawn-timer` 分片 —— 从 live client data 取剩余时间/总时长/是否阵亡，做一个倒计时浮层。
- **不做的理由**：第一，它属于"代打"侧的手感类功能，不提供任何决策信息；
  第二，它需要**常驻悬浮窗**，与"不要很多窗口"的取向直接冲突（用户已明确表达不喜欢多窗口）。
- **若要捡起来**：数据我们本来就有通道（`https://127.0.0.1:2999/liveclientdata/allgamedata` 的 active player）。
  但形态必须换成**对局页内嵌**，不能是浮层，才值得考虑。

### 5. 自动开始匹配（auto matchmaking / auto start）

- **AK 对应**：`matchmaking-controller` 一整条 lobby 流程（自动开局、邀请好友、等被邀请者…）。
- **不做的理由**：这是最典型的"替你把游戏玩掉"——它要**替玩家开局**，
  还要替玩家和真实队友协商（等人、邀请）。同时踩中第 1、2 条。
- **现状**：保留**手动**工具（一键启动客户端、客户端急救）就够用。

### 6. 一键写入推荐符文页（rune injection）

- **用户已澄清**：**不要**做成 AK 那种单独悬浮窗，也不想要很多窗口；
  真正想要的是**房间信息统计**那种信息呈现（见需求「房间成员信息统计」）。
- **不做的理由**：写符文是**改玩家账号上的持久数据**，会覆盖他自己手配的页；
  且正确性依赖版本与英雄，写错比不写更糟。这是一个"不可逆 + 对外可见"的操作。
- **会做什么（另一条线）**：把推荐符文/推荐出装**展示**出来，由玩家自己决定抄不抄。
  展示是"看清"，写入是"代打"，分界线就在这里。

### 7. 局内自动操作（自动走位 / 自动技能 / 自动买装备 / 自动补刀）

- **红线**，不再是"值不值"的问题：需要注入或模拟输入、且替玩家操作，
  必然违反游戏规则、有封号风险。不讨论、不实现。

### 8. 其他被问到过的

- **自动同意好友申请**：社交关系要人确认（同上）。
- **自动接受"再来一局"**：等价于替玩家重新排队进游戏。

## 三、边界表：哪些"像自动化"但我们做了

列在这里是为了说明**分界线画在哪**——不是"自动化一律不做"。

| 已做能力 | 为什么不算越界 |
| --- | --- |
| 一键领取（任务 / 奖励 / 事件中心） | 玩家本来就会领，只是省点击；不改任何决策 |
| 自动接受**对局**（准备确认） | 只涉及自己，误判成本 = 少打一局 |
| 自动选人 / 禁用 | 默认 `enabled: false` + `advisoryMode: true`（先给建议）；锁定是玩家自己选的策略，不是默认行为 |
| 大乱斗抢英雄 | 同上，且换人间隔 0–30s 可调 |
| 快捷消息发送（`Ctrl+F1/F5/F7/F9/F11/F12`） | 文本玩家写、按键玩家按 |
| 客户端急救（秒退 / 退出房间 / 退出结算 / 重连 / 清失败提示） | **手动**按钮；有副作用的两项带二次确认 |

## 四、通用结论

- 这个应用的目标是**"让玩家更懂局面"**，不是"让玩家不用玩"。
  把对局自动化掉之后，赢的也不是自己——那正是"做了反而无趣"的意思。
- 判断新需求时，只要发现它落在「替玩家做决定 / 替玩家花代价 / 替玩家操作」这三者之一，
  默认答案就是不做；真要做，也必须默认关闭并保留当场确认。
- 想捡起上面任何一条，接口落点都写在各条里；加命令的完整流程见
  [改造方案](REFACTOR_PLAN_2026-09-22.md)。
