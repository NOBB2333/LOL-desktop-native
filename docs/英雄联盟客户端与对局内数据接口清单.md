# 英雄联盟客户端与对局内数据接口清单

> 汇总日期：2026-09-30 · 适用客户端：国服 / 腾讯服（`nj100`、`tj101` 等平台）
>
> 目的：**为「接入 AI 大模型」做数据盘点**。这份文档回答两个问题：
> ①**在客户端里**（还没进游戏）能拿到哪些信息、分别走哪个接口；
> ②**进了游戏之后**能拿到什么数据、走哪个接口。
> 每一项都给了**完整的请求与响应示例**，可以直接照抄成代码或喂给模型。

---

## 0. 先看结论：三个数据层，能力完全不同

| 层 | 地址 | 要不要授权 | 什么时候有数据 | 本项目里谁能用 |
|---|---|---|---|---|
| **A. LCU（客户端本地 API）** | `https://127.0.0.1:{port}`，端口与令牌在 lockfile 里 | **要**（Basic 认证，用户名 `riot`） | 客户端一启动就有 | 全部页面 |
| **B. Live Client Data（对局内）** | `https://127.0.0.1:2999/liveclientdata/…` | **不要**（完全免授权） | **只有正在打那一局时**才有 | 对局录制、观战面板 |
| **C. 第三方 / 云端** | SGP、CommunityDragon、OP.GG… | 各不相同 | 见各节 | 战绩、技能数值 |

**关键区别**：A 是「客户端知道的一切」（好友、房间、战绩、商店…），
B 是「这一局里发生的事」（十个人的实时状态、装备、事件）。
它们**不是同一份数据**——比如「实时血量/复活读秒」只有 B 有，
「好友列表」只有 A 有。做 AI 功能时必须说清用哪一层。

## 1. 怎么连上 A 层（LCU）

LCU 的端口和令牌**每次启动都会变**，写在 lockfile 里：

```
// Windows 路径（注意有两个可能位置，先看第一个）
%LOCALAPPDATA%\Riot Games\Riot Client\Config\lockfile
C:\Riot Games\Riot Client\Config\lockfile
```

**lockfile 内容**是一行冒号分隔的文本（**不是 JSON**）：

```
LeagueClient:12345:54321:abcdefghijklmnop:https
   │        │     │        │            └── 协议（https）
   │        │     │        └── 密码（Basic 认证用，用户名固定当 riot）
   │        │     └── 端口（HTTPS 用这个）
   │        └── PID
   └── 进程名
```

对应的请求写法：

```bash
# 从 lockfile 里取出密码与端口后：
curl -k --noproxy '*' \
  -u "riot:$(cut -d: -f4 lockfile)" \
  "https://127.0.0.1:$(cut -d: -f3 lockfile)/lol-summoner/v1/current-summoner"
```

⚠️ **三个必踩的坑**（本项目 2026-09 实测）：

1. **必须显式禁用代理**。Clash（`127.0.0.1:7890`）或深信服 aTrust 在跑时，
   Python `urllib` / curl 会把 `127.0.0.1` 的请求也塞进隧道，
   报 `Tunnel connection failed: 502 Bad Gateway`——**看起来像客户端没起来**。
   → `curl` 加 `--noproxy '*'`；Python 用 `ProxyHandler({})`。
2. **证书是自签的**，要 `-k` 或跳过校验。
3. lockfile 是**启动时**写的，客户端重启一次端口就变——**别缓存端口**。

## 3. C 层：SGP（跨大区战绩，十人阵容的唯一来源）

**基址**：`https://{host}/match-history-query/v1/products/lol/…`
`host` 从 LCU 的 `/lol-gameflow/v1/session`（或 `/lol-summoner/…`）里带的 SGP 端点推出来，
平台代号（`platform_id`）形如 `NJ100`、`TJ101`。

| 接口 | 用途 | 关键点 |
|---|---|---|
| `GET …/player/{puuid}/SUMMARY?startIndex=0&count=20` | **任意 puuid 的战绩列表** | 认**任意** puuid（不只自己） |
| `GET …/{platform_id}_{gameId}/DETAILS` | **单局十人完整数据** | **十人阵容必须走这个** |
| `GET …/{platform_id}_{gameId}/SUMMARY` | 单局摘要 | 不含十人明细 |

**SUMMARY 示例**（列表项）

```json
{
  "games": [
    {
      "endOfGameResult": "GameComplete",
      "gameCreation": 1759100000000,
      "gameDuration": 1832,
      "gameMode": "CLASSIC",
      "gameType": "MATCHED_GAME",
      "gameVersion": "15.19.1.1",
      "queueId": 420,
      "json": {
        "gameId": 7123456789,
        "participants": [ { "puuid": "6f8a…", "championId": 136, "teamId": 100,
                            "teamPosition": "MIDDLE", "individualPosition": "MIDDLE" } ]
      }
    }
  ]
}
```

**DETAILS 的关键增量**（相对 SUMMARY）：

- 十人 `participants` 全部带 `puuid` + **`teamPosition`**（这就是消歧分路的权威来源）
- `perks.styles[].selections[].perk`（符文）
- `challenges`（挑战数据）
- 每人完整 `stats`（伤害、视野、补刀、金币…）

## 4. C 层：CommunityDragon（技能真实数值）

**基址**：`https://raw.communitydragon.org/latest/`

| 接口 | 用途 |
|---|---|
| `/game/data/characters/{小写别名}/{小写别名}.bin.json` | **单英雄技能数值**（占位符的真值） |
| `/plugins/rcp-be-lol-game-data/global/zh_cn/v1/summoner-spells.json` | 召唤师技能（含中文名 + 冷却） |

### 4.1 技能变量取值怎么对上的

CDragon 的 `mSpellCalculations` 的**键名和 LCU 文案里的 `@名字@` 是同一套**——
拉莫斯 Q 的 `@PowerBallDamage@` 在这边就叫 `PowerBallDamage`，**不需要映射表**。

```json
{
  "Characters/Rammus/CharacterRecords/Root": {
    "mCharacterPassiveSpell": "Characters/Rammus/Spells/RammusPAbility/RammusP",
    "spells": [
      "Characters/Rammus/Spells/PowerBallAbility/PowerBall",
      "Characters/Rammus/Spells/DefensiveBallCurlAbility/DefensiveBallCurl",
      "Characters/Rammus/Spells/PuncturingTauntAbility/PuncturingTaunt",
      "Characters/Rammus/Spells/Tremors2Ability/Tremors2"
    ]
  },
  "Characters/Rammus/Spells/PowerBallAbility/PowerBall": {
    "mSpell": {
      "DataValues": [
        { "name": "QBaseDamage", "values": [40, 80, 120, 160, 200, 240, 280] },
        { "name": "APRatio",     "values": [1, 1, 1, 1, 1, 1, 1] },
        { "name": "SlowPercent", "values": [30, 40, 50, 60, 70, 80, 90] }
      ],
      "mSpellCalculations": {
        "PowerBallDamage": {
          "mFormulaParts": [
            { "__type": "NamedDataValueCalculationPart", "mDataValue": "QBaseDamage" },
            { "__type": "StatByNamedDataValueCalculationPart", "mDataValue": "APRatio" }
          ]
        }
      }
    }
  }
}
```

⚠️ **CDragon 的键大小写不固定**（`CharacterRecords` vs `characterrecords`），
必须做**不区分大小写**的查找。

**取值有四级降级**（越靠后越弱，全取不到就**保留 `@…@` 原文**）：

| 级 | 公式形状 | 怎么取值 |
|---|---|---|
| 1 | 只有一段 `NamedDataValueCalculationPart` | 直接用那个 `DataValues` 数组 |
| 2 | `NamedDataValue` + `StatByNamedDataValue` | 用基础值那组，并把系数与**系数乘的属性**记下 |
| 3 | 名字**直接**是 `DataValues` 名（`RollDuration` / `AOEModifier`…） | 直接拿那一组 |
| 4 | 只有一段 `BuffCounterByNamedDataValueCalculationPart` | 见下「层数型」——**不能**拿被消费的那个数值 |

### 4.1.1 「层数型」：`@BurstBonusTrueDamageToChamps@` 为什么印的是 2 而不是 0.031%

这是 2026-10-02 才搞清的一档，**照抄公式里的数值会印出完全错误的数字**。

龙王 Q 的公式（CDragon 实测原文）：

```json
"BurstBonusTrueDamageToChamps": {
  "mFormulaParts": [
    { "__type": "BuffCounterByNamedDataValueCalculationPart",
      "mDataValue": "QMaxHealthTrueDamagePerStack",
      "mBuffName": "{c9372c6b}", "mIconKey": "%i:asolStackIcon%" }
  ],
  "mDisplayAsPercent": true
}
```

而同一个 `mSpell.DataValues` 里：

| 数据值 | 值 | 说明 |
|---|---|---|
| `QMaxHealthTrueDamagePerStack` | `0.00031` | **每层**星尘的伤害系数（按最大生命值） |
| `QMassStolen` | `2` | 每次吸收的**星尘数** |

客户端文案实际渲染出来是 `2 / 2 / 2 / 2 / 2 / 2 / 2`（就是 `QMassStolen`），
**不是** `0.031%`。

> **判据**：公式里只有一段 `BuffCounter…` 时，这一项的输出**不是**它消费的那个数值，
> 而是「同类里读起来像个数/层数的那一项」——名字里带
> `Mass` / `Stack` / `Stun` / `Count` / `Charge` / `Soul` / `Essence` / `Token` / `Splinter`
> 的优先。实测样本 4 例全部符合：`BurstBonusTrueDamageToChamps` 与 `QPassiveScaling`
> （龙王）取 `QMassStolen`，`ResistsForTooltip`（盖伦 W）取 `BuffCounterPerKill`，
> `EPassiveScalingExecute`（龙王 E）取 `EExecutionStacks`。
>
> 认不出层数项时**整项不输出**（保留原文），绝不拿 `0.00031` 凑数。

### 4.2 「它是什么加成」——四种加成口径

这是最容易搞混的地方，2026-09-30 起逐个实测确认：

**① 系数型（`StatByNamedDataValueCalculationPart`）：变量名 / `mStat` 说明了乘什么**

属性有**两个**来源，**优先用官方枚举 `mStat`**（权威，不用猜名字），没有才退回名字启发式：

| `mStat` | 属性 | 实测出处 |
|---|---|---|
| `2` | **攻击力** | 金克丝 W `ADRatio`、亚索 Q `ADRatio`、盖伦 E `tADRatio` |
| `7` | **移动速度** | 龙王 W `DashSpeed` |
| `9` | **暴击伤害** | 亚索 `CurrentCritDamage` |
| `12` | **最大生命值** | 盖伦 W `ShieldHealthRatio`、龙王 E `ExecuteHealthThreshold` |
| `1` / `6` | 护甲 / 魔法抗性 | 拉莫斯 W（社区长期记录，本样本未复现） |

> ⚠️ `mStat` **大多数时候是不写的**（19 处 `StatByNamedDataValue` 里只有 6 处带），
> 所以名字启发式**必须保留**，两者互补。
>
> ⚠️ 名字启发式的坑：盖伦 W 的 `ShieldHealthRatio` 字面带 `Health`，启发式会猜成
> `Health`（生命值）；但 `mStat: 12` 说的是**最大生命值**。**有 `mStat` 就要听它的。**

| 变量名 | 乘的属性 | 实例 |
|---|---|---|
| `APRatio` / `APPerSecond` / `BurstAPRatio` | **法术强度** | 龙王全套技能 |
| `ADRatio` / `RocketTAD`（`mStat: 2`） | **攻击力** | 金克丝 Q/W、猴子 Q |
| `DamageArmorRatio`（`mStat: 1`） | **护甲** | 拉莫斯 W |
| `DamageMRRatio`（`mStat: 6`） | **魔法抗性** | 拉莫斯 W |

**② 无系数的属性归因：公式里没有 `StatByNamedDataValue`，但消费的数据值名字说明了属性**

`BurstBonusTrueDamageToChamps` 自己叫不出属性，但它消费
`QMaxHealthTrueDamagePerStack` → **最大生命值**。这类项**只有属性、没有系数**
（`ratioStat` 有值而 `ratio` 为空），前端显示成「按最大生命值算」而不是伪造一个系数。

**③ 逐级系数：`ratio` 与 `ratios`**

系数本身也可能逐级不同。实测金克丝 W 的 `ADRatio` = `1.4 / 1.5 / 1.6 / 1.7 / 1.8`。

> 只保留第 0 格会让「升到 5 级」的加成看上去和 1 级一样。
> 所以全等时给一个 `ratio`，**确实逐级不同时额外给 `ratios` 整条**。

**④ 表达式型（`@Name*100@`）：`*100` 的意思是「这个分数按百分数说」**

CDragon 存的是**原始分数**，客户端文案用 `*100` 转成百分数：

| 变量 | CDragon 原始值 | 客户端文案 | 显示 |
|---|---|---|---|
| 拉莫斯 R `SlowAmount` | `0.2, 0.3, …, 0.8` | `@SlowAmount*100@%` | `20 / 30 / … / 80%` |
| 猴子 Q `ArmorShredPercent` | `0.05, 0.10, …, 0.35` | `@ArmorShredPercent*100@%` | `5 / 10 / … / 35%` |
| 龙王 Q `AOEModifier` | `0.5` | `@AOEModifier*100@%` | `50%` |
| 金克丝 Q `AoEDamageMult` | `0.8` | `@AoEDamageMult*100@%` | `80%` |

> ⚠️ **`%` 是写在占位符外面的**（`@SlowAmount*100@%`）→ 渲染时必须
> **只输出数字**，再补一个百分号就会变成 `80%%`（09-30 实测踩到过）。
>
> ⚠️ **「是分数」有两条判据，缺一不可**：计算项自己标了 `mDisplayAsPercent: true`
> （`BurstBonusTrueDamageToChamps` / 拉莫斯 `MinimumMoveSpeed` 就是），
> **或者**取值全部落在 `[0, 1]` 且至少一个非 0。
> 第二条是必须的——`AOEModifier` 是纯 `DataValue`，**没有** `mDisplayAsPercent`
> 可读（那个字段只存在于计算节点上），只能靠区间判。
> 反过来 `TooltipTakedownCooldownMultiplier = 90` 这种「已经是百分数」的不算分数。

**⑤ 取不到的三类（不许编数字）**

| 类型 | 例子 | 为什么取不到 |
|---|---|---|
| 随**英雄等级**插值 | `@MinimumMoveSpeed@` | `ByCharLevelInterpolationCalculationPart`，要知道当前等级 |
| 引**实时属性** | `@BonusArmorTooltip@` | 随装备/符文变 |
| 客户端拼接位 | `@SpellModifierDescriptionAppend@` | 不是数值，是拼装备加成的**位置**，本来就该空 |

### 4.2.1 客户端文案里的富文本（不是纯文本）

`description` / `dynamicDescription` 是**自带标记的富文本**，直接插值会把标签印出来：

| 写法 | 含义 | 处理 |
|---|---|---|
| `<magicDamage>…</magicDamage>` | 魔法伤害着色 | 映射成样式 span |
| `<speed>` `<scaleArmor>` `<scaleMR>`… | 关键词着色 | 同上 |
| `<font color='#3458eb'>2 / 2 …星尘</font>` | **关键词上色**（龙王星尘就是） | 只放行 `#rgb`/`#rrggbb` 十六进制，防 CSS 注入 |
| `<br>` | 换行 | → `<br />` |
| 白名单外的标签 | —— | **当文本转义**（不是丢掉），避免句子断掉 |

> ⚠️ 颜色属性是第三方字符串，**只认十六进制**，其余一律退回默认色——
> `red;background:url(...)` 这类不能让它进 `style`。

### 5.3 ⚠️ 这一层的**硬限制**（实测，别浪费时间找）

1. **`allPlayers` 官方字段集里没有 `puuid`**。完整字段只有：
   `championName / isBot / isDead / items / level / position / rawChampionName /
   respawnTimer / runes / scores / skinID / summonerName / summonerSpells / team`。
   → 所以**按 puuid 合并录制帧永远配不上**，只能按**召唤师名**配。

2. **没有伤害数据**。任何「他打了多少伤害」都拿不到。

3. **没有 `ITEM_PURCHASED` 事件**。要「某时刻他是什么装备」只能**轮询 `items[]` 差分**。

4. **`gameData` 里没有 `gameId`**！只有 `gameMode / gameTime / mapName / mapNumber / mapTerrain`。
   → 局号必须走 **`GET /lol-gameflow/v1/session` 的 `.gameData.gameId`**。
   （09-27 事故：`appendFrame` 自己读 `gameData.gameId` → 永远 0 → **一帧都没存**。）

5. **`allPlayers` 不含组队字段**。开黑标记要靠 gameflow session 的 `teamParticipantId` 合并。

6. **实时技能冷却剩余秒数拿不到**。
   - `activePlayer.abilities.<slot>` 只有 `abilityLevel / displayName / id / raw*`，
     **没有 `cooldown` / `remaining`**。
   - `allgamedata` 共 **99 个字段**，**零个**冷却/计时字段。
   - 唯一真正的倒计时是 **`respawnTimer`**（复活读秒），已经在用。
   - 所以只能**算**：`实际冷却 = 基础冷却 ÷ (1 + 技能急速/100)`；
     但 `championStats` **只有本人有** → **敌方技能急速只能估**。
     **「剩余秒数」不可得，不许伪造。**

## 8. 做 AI 功能时的注意事项

1. **时延分级**：
   - 本地 LCU / Live Client Data = **毫秒级**，可以每个回合都喂给模型。
   - SGP / CommunityDragon = **公网，几百毫秒到几秒**，要缓存。
   - 本机所有外网出口是**同一个境外 VPS**（实测）→ 未登录 GitHub API
     只有 60 次/小时（**按 IP**，共享）→ 会被打满，返回 **403** 而不是连不上。

2. **「不知道」要能表达**。队伍级占比拿不到整队数据时**一律写 `null`** →
   前端显「—」。**绝不用 0 或 100 顶替「不知道」**。这条对喂给模型同样重要：
   模型看到 0 会当成真值来推理。

3. **不要把标签当文本**。技能文案带 `<speed>` `<font color='#3458eb'>`，
   占位符有 `@Name@` 和 `@Name*100@` 两种形态 → 要么白名单渲染，
   要么在喂模型前**先替换干净**。

4. **两个「空」要分开说**。比如「这一局没录制」和「录制功能从没生效过」
   是两个不同的状态（本项目用 `recordedGames` 计数区分），别合并成一句话。
