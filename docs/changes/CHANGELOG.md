## 未发布（开发中）

### 实时对局（选人 / 对局）

- **选人阶段十人资料的加载明显变快**。原先整批被拆成「我方一轮 → 发布 → 敌方一轮」，
  两轮之间的等待让耗时几乎翻倍；而且批次的请求和英雄头像挤在同一条网络配额上，
  排队久了会被自己的超时判死、整批退回 10 秒后重试。现在十人一遍跑完、只发布一次，
  批次另有一条专属配额，不再和头像抢道。
- **头像/图标从「排队一个一个取」改成真正的并行获取**。原先每条请求通道只有一个工作线程，
  同一条通道上的请求被**严格串行**执行——前端即使一次发 200 多个头像请求，到了后端也是一个一个过。
  现在图标取字节有**独立的通道**（独立配额 + 4 个并行工作线程），
  既不再和交互式查询（点开英雄看技能、段位战绩）抢位置，本身也能并行下载。
  英雄页首屏 200 多个头像的加载时间因此从「个数 × 单张」量级回落到「个数 ÷ 并行」量级。
- **英雄头像恢复加载**，并修掉一个会把它**永久焊死**的缓存缺陷。上一版为了省流量给头像加了
  「滚到可见才请求」的判断，但在本应用的内嵌浏览器里那个回调不触发，结果是一个头像都不加载；
  已改回始终请求，改成在缓存层限制并发数。此外，前端那句「按 `(类型, 编号)` 记住结果」的缓存
  曾把**空结果**也留着——某一次取图失败（例如客户端短暂未连上）之后，同一个图标就再也不重试，
  表现正是「很多头像现在完全加载不出来」。现在空结果不缓存，下一次会真的重新请求。

### 英雄技能资料

- 英雄页新增「查看技能」入口：展开后可看被动与 Q/W/E/R 的技能名、图标、逐级冷却/耗蓝/射程。
- 技能文案里的官方占位符（如 `@TotalDamage@`）原先只能原样显示并附说明；现在会尽量替换成真实数值，
  并且**系数直接写在技能文案里**（如 `30 / 60 / 90 / 120 / 150 + 60% 法术强度 + 3% 最大法力值`），
  不再把同一条数值在文案下方再列一遍。
- 数据来源：技能名、槽位与描述走**本机客户端**（因此已按客户端语言显示）；占位符背后的逐级数值走
  CommunityDragon 的公开数据。**需要本机开着客户端**，离线时只有英雄列表与 OP.GG 统计可用。

### 观战面板

- **阵亡的圆点不再移动**。之前阵亡只做了灰化，位置仍在按分钟帧插值，看起来像尸体在跑；现在会钉在
  最后一次活着时的坐标上，并保留右下角的复活读秒。
- 阵亡状态只有「本机录制」里才有；没有录制时不灰化、不读秒，也不会伪造一段猜测的死亡区间。

### 每波团

- 「出装」一档改为显示**团战开始那一刻**的装备，而不是终局六件。副标题会明确区分：
  有录制是「团战时刻的出装（本机录制 · 04:18）」，没有则是「本局终局出装（这一局没有本机录制）」。
